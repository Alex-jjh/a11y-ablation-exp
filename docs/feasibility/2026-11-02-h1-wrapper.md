# H1 wrapper, step budget and trace codebook (2026-11-02)

> **Summary:** Engineering record, not data. `scripts/probe/breakingweb/h1_wrapper.py` runs one H1 episode and fixes all six problems of the pipeline smoke test, without editing the clone. An offline test with a scripted fake model passes 34 of 34 checks: it solved `reddit_compose_message` on the clean build in 9 steps, stored every field, recomputed every prompt hash from the trace alone, and refused to start on a changed bundle. Request-shape probes (13 small calls, no BreakingWeb content) show that all four pilot-relevant models accept the wrapper's reasoning fields and return a readable reasoning summary. GPT-5.6 does so only when `reasoning.summary` is sent; without it, it returns one encrypted block. Anthropic `budget_tokens` cannot be used: the API rejects it on these models, so depth is set by effort. The step budget changes: under the DESIGN cap (1.5 x expected_steps), 74 of 777 successful published runs (9.5%) would have run out of steps; under the proposed cap, 3 (0.4%). The mean cap over the 64 sample tasks rises from 23.4 to 29.6. The codebook (`studies/v2-pilot/TRACE-CODING.md`) and the observer prompt (`studies/v2-pilot/trace_observer_prompt.md`) are written; no observer has run.

Question served: is the H1 harness of DESIGN §3 ready for Stage 0s: does it send what the protocol says, record what the analysis and the trace observers need, refuse a wrong build, and avoid failing tasks on budget alone? Model rule: only the Bedrock models on `codex-DO-NOT-DELETE`. No Gemini call was made; published Gemini runs were read as recorded data.

## 3. Step budget (observed from recorded data; no study-model run used to fit it)

Rule (`h1_budget.py`, docstring): `cap = min(60, max(int(1.5 x expected_steps), ceil(K x L_ref) + A))`.

| Term | Value | Grounds | How it could be wrong |
|---|---|---|---|
| L_ref | Gemini reference actions that need an H1 step, plus one scroll per replay wheel op, plus 1 for the final message | Replay scripts (`/tmp/amt-syn/bw-replay/final/*/scripts/`); browser-use clicks off-screen elements by index, but H1 sees only the viewport | One scroll per wheel op is a lower bound. Nested scrollers need a hover first: the fake agent needed `hover` + `scroll` for reddit's sidebar, and the smoke agent found the same route |
| K | 1.41 = 95th percentile of need/L_ref over 777 successful published clean runs of 6 panel models on the 195 reference tasks (median 1.0, 90th 1.26, 99th 2.14) | `~/.hf-stage-bw/*/tasks/*__clean/trajectory.json` | Browser-use agents are not H1 agents. They take up to 4 actions per step and need no scroll to find an element |
| A | 10 | The only H1 evidence: both smoke runs spent 11-12 steps reaching a below-the-fold link on a task with L_ref 8 (n = 2, one task) | Fitted to n = 2. It may be too small for envs with deeper nested scrollers, or too large elsewhere |
| CEIL | 60 | Stock browser-use's own cap; bounds cost | 3 successful published runs need more than the cap (2 of them more than 60) |

Results:

| | DESIGN cap (1.5 x expected) | Proposed cap |
|---|---|---|
| Successful published runs that exceed the cap, all 195 reference tasks | 74 of 777 (9.5%) | 3 of 777 (0.4%) |
| Same, the 64 sample tasks | 29 of 274 | 1 of 274 |
| Mean cap, 64 sample tasks | 23.4 | 29.6 (44 tasks raised; max 60) |
| reddit_compose_message (smoke task) | 10 | 22 |

- The proposed cap would not have saved the smoke runs on its own: they reached the form at steps 13-14 and needed about 4 more steps to fill and send. They would have finished at about step 18, under 22.
- Cost (inferred): only runs that reach the cap get longer. At the cost model's clean success of 0.7, mean H1 steps per run rise by about 0.3 x 6.2 ≈ 1.9 steps, roughly 10-15% more H1 input tokens. That is before the 1.77x tokens-per-step correction the smoke record already requires.
- What would change it: Stage 0s reports, per task, the step at which the goal page was first reached (TRACE-CODING §5) and F4 (stopped on route). If F4 exceeds 5% of clean runs, A is raised before Stage 1; if cap hits are rare, A can be lowered. Either change voids nothing, because it happens before Stage 1. After Stage 1, a cap change voids Stage 1 (design.yaml `change_rule`).

## 4. Offline test (observed)

`h1_selftest.py`, private copy `/tmp/amt-syn/h1-test/BreakingWeb` (release 052f0f0 plus the four bind diffs, reddit clean build), port 8396-8398, fake Bedrock client, no LLM. Output: `/tmp/amt-syn/h1-test/selftest-final/selftest.json`; 34 of 34 pass.

- T1, reference run. An Anthropic-shaped fake followed the recorded Gemini route by role and name, read from the observation it received. It solved `reddit_compose_message` in 9 steps (`hover`, `scroll`, then the 7 route actions), with evaluator success 1.0 and `end_reason: agent_finished`. Every step has every field. Every prompt hash was recomputed from the trace alone (system prompt, stored observation texts, actions, summary markers). The texts the fake received equal the stored observation texts. No temperature was sent, M1 passed on the document and both assets, and the isolation self-check passed. Files are read-only, SHA256SUMS is valid, and the run directory cannot be reused.
- T2, failed run. A GPT-shaped fake that only scrolls hit the test cap of 12 steps (`step_cap`). The forced evaluation is stored with its failed check. The trim threshold was lowered to 6,000 estimated tokens, so 9 summary calls ran (10 of 12 steps had a trimmed history): requested temperature 0.0, sent none, no failures, and the summary text reached the agent's prompt. Reasoning visibility is `encrypted`, and the trimmed prompts were recomputed from the trace.
- T3: refusals in 5 of 5 cases (a changed file hash, a wrong `--expect-bundle`, a disallowed model id, the unbuilt cell `names+`, a cell that does not match the build), each before any server, model call or trace.
- T4: the pass-A packet has no evaluator, cell, run id, repeat or model; pass B adds only the evaluator; the key file maps both back to the trace sha256.
- After the test, the shared clone and the private copy show only the four allowed bind diffs.

Not tested: a real model through `run`, a variant build, the browser-use harness, concurrency, the 120 s step timeout, and the observation-layer cells (`names+`, `names50`, `fmt_wrap`, `pos_info`). The wrapper refuses those cells until Stage 0 builds them.

## 6. Decisions for Alex

1. **Pilot model and effort.** The wrapper takes any of the six allowed ids. DESIGN, design.yaml and cost.json still name Opus 5.5 and GPT-5.6-sol. For Sonnet 5.5 the wrapper's default effort is `high`, the provider default made explicit; Opus 5.5 is `medium` and GPT-5.6 is `medium`. GPT-5.6's Bedrock default value is [unverified].
2. **GPT reasoning summary.** Send `reasoning.summary: detailed` (proposed: the trace observers need it), or omit it and accept encrypted-only reasoning for GPT-5.6.
3. **Step budget.** Adopt the proposed cap (mean 29.6 over the sample, 0.4% of published successes over it) in place of 1.5 x expected_steps. This changes DESIGN §3 and design.yaml `step_cap`, and cost.json must be recomputed.
4. **Step timeout.** A step whose model call takes more than 120 s ends the run (as shipped). Proposed: count it as an infrastructure failure (M8, rerun), not an agent failure.
5. **Trace coding** (TRACE-CODING §8): code all H1 traces or a sample; which models are O1 and O2; who codes the 30 human-reference traces.
