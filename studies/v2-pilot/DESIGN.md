# v2 pilot: design

> **Summary:** The pilot runs two current models (Claude Sonnet 5.5 and GPT-5.6-sol on Bedrock) on 64 BreakingWeb tasks in the BrowserGym AXTree text harness under the clean apps, a byte-identical rebuild served like a variant, each of the six source-level defect kinds on the tasks whose path carries it, an add-back control and a half-dose for names, a label-function sham, a landmark-keeping format control and a positive control, with a smaller browser-use arm for names. It measures run-to-run noise, the variance components that size the main study, form and format effects, and the on-path drop of each kind; it tests two directional predictions (names) and four equivalence predictions (landmarks, headings, 10-point margin). It is a development study, not the main study. 4,718 agent runs, about 108,000 LLM steps, estimated at $3,400 to $6,000 from the tokens measured in the 2026-11-02 wrapper smoke (the GPT price is a placeholder and GPT's reasoning tokens are not reported). Revised after three reviews; section 11 answers every point. Models and cost changed on 2026-11-02 (section 11, last row); the pre-run checklist is `READINESS.md`.

## 1. Research question

**Question.** For a current LLM web agent that reads the BrowserGym accessibility-tree text, how much does task success drop when one kind of accessibility information is removed from the app source while the page stays the same for a sighted mouse user, on tasks whose solution path passes through that information; and how large are run-to-run noise, form effects and format effects next to that drop?

**Estimand.** Information-use attribution: the drop caused by removing one kind of information, completely, from apps that carry it richly, with function and look held fixed. It is not the harm of a realistic defect on a real site (section 9).

**Why a pilot first.** No close-read gives an effect size for removing landmarks, headings, table semantics, names or label associations from an LLM agent's observation. The nearest are alt text and HTML tags on about 54 VisualWebArena tasks with 2024 models ([Chi2024](../../../ai-accessibility-paper/literature/papers/L_Chi2024.md)), per-attribute removal on a handful of instances ([Enomoto2026a](../../../ai-accessibility-paper/literature/papers/L_Enomoto2026a.md)), and whole-tree pruning ([Kerboua2025a](../../../ai-accessibility-paper/literature/papers/L_Kerboua2025a.md): 51-59% of lines cut for 1.5-4.7 points) (DQ-predict, "Prior effect sizes"). No source gives variance components for current models on these tasks, and power must be planned from them ([Card2020](../../../ai-accessibility-paper/literature/papers/L_Card2020.md), [Miller2024](../../../ai-accessibility-paper/literature/papers/L_Miller2024.md), [MandujanoReyes2026](../../../ai-accessibility-paper/literature/papers/L_MandujanoReyes2026.md); DQ-analysis finding 6). No source measures a form or format effect for an LLM web agent at our doses (DQ-verify, Gaps). The brief lists these as measurements that must come before the design is frozen (brief, "What we must measure", items 5 and 7). This is Phase 1 of DQ-predict Option C: development models on a development task split, with the remaining tasks and the held-out models sealed.

**Novelty gate.** DQ-position lists unread nearest-work leads (A11y-CUA, CHI '26; Ersoy2025's ARIA-removal arm; WebSuite; Huq et al. 2023; Lee et al. ICLR 2025). Before Stage 0s the dated literature search DQ-position requires is run and logged, and A11y-CUA and Ersoy2025 are close-read. What only this design measures, against those neighbours: per-kind effects with function and look held fixed by gates, an add-back control that restores the information on the same page, a dose point, and step-level failure measures (section 4.6).

## 2. Claims the pilot can and cannot support

| The pilot can support | The pilot cannot support |
|---|---|
| The rerun band of each model in each harness on these tasks, per cell (half-vs-half clean difference, run disagreement) | Any claim about tasks outside the pilot sample; the 88 sealed tasks are untouched |
| Variance components per kind (task, task x cell, run) for the main-study power simulation | That a kind "does not matter" below 10 points. The equivalence margin is 10 points because that is what 62-64 tasks can show (`power.json`: a true null is graded hit with probability 0.79 to 0.995 at margin 10, 0.35 to 0.81 at margin 5). Equivalence may also be redundancy, not non-use ([Hooker2019](../../../ai-accessibility-paper/literature/papers/L_Hooker2019.md)) |
| Whether a form or format change moves success: `names+` against `names` (information with form held), `fmt_wrap` against clean (indentation with landmarks held) | Effects on real defective websites, or at realistic doses (D-005: mechanism only; DQ-dose recommends no realistic-dose claim) |
| The on-path drop per kind with a task-clustered interval, per model and harness, labelled pilot results | Ranked or confirmed kind effects for a paper: the confirmatory test of the main study runs on the sealed tasks with held-out models |
| Whether the pipeline detects a large information loss (`pos_info`) and stays flat under a null served like a variant (`none`) | Effects on vision or screenshot agents in general: H1 is text-only; H2 adds the screenshot for names only. Claims are scoped to text-AXTree agents |
| Whether BrowserGym and browser-use differ in the names effect of the same build | Claims about people who use assistive technology (D-002, D-006: agents are the object) |
| Actual tokens, steps, latency, truncations and refusals per run, for the main-study budget | Generalisation to other model versions; hosted models change without notice ([Chezelles2024](../../../ai-accessibility-paper/literature/papers/L_Chezelles2024.md)) |

The pilot registers two directional predictions (names, family F1) and four equivalence predictions (landmarks and headings, family F2) so that its hits and misses are informative ([Hofman2023](../../../ai-accessibility-paper/literature/papers/L_Hofman2023.md); DQ-predict Phase 0b). They are confirmatory for the pilot sample only.

## 3. Environment, builds and harnesses (fixed settings)

- **Environment.** BreakingWeb (D-007), local clone `~/.workspace/_refsrc/BreakingWeb` at release `052f0f0`, Chromium 125.0.6422.26 (Playwright 1.44), all binds on 127.0.0.1, research use only (no LICENSE; [2026-10-29-breakingweb.md](../../docs/feasibility/2026-10-29-breakingweb.md)). Backend default seed per session, as the stock harness creates sessions ([2026-10-30-replay-feasibility.md](../../docs/feasibility/2026-10-30-replay-feasibility.md) §1.2). Remote requests are aborted in every arm; page Date fixed at load as in the replay.
  - Grounds for the settings: under them the scripted reference replays are deterministic (of the 310 input-pure tasks, 195 pass 3/3 and 115 fail 3/3; replay record §2). That replay has no LLM, so it says nothing about agent run noise; the pilot measures that (section 4.4).
  - Date drift: three seeders call `datetime.now`, so data-bearing names drift by day ([2026-10-30-on-path-dose.md](../../docs/feasibility/2026-10-30-on-path-dose.md) §6). The schedule is blocked by day (section 7): every run of a task, in every cell, model and harness, runs within one local calendar day, and no run starts in the 30 minutes before midnight. `faketime` is not installed and the clone may not be patched, so the clock itself is not frozen.
- **Builds.** Each cell is a built bundle identified by its sha256 prefix (`design.yaml: bundles_sha256_prefix`). The codemod that builds them is frozen and hashed in Stage 0 (`design.yaml: codemod`; current file sha256 `02b3190f`, while the on-path record's agreement check used `71a8d729`). Every bundle is rebuilt from the frozen codemod and re-gated. The `none` rebuild is byte-identical to clean, but is served from its own checkout, backend process and 127.0.0.1 port, started and restarted on the variant schedule, so that it carries every serving difference a variant carries.
- **Harness H1, BrowserGym AXTree text (primary).** `breakingweb/agent.py` `LLMAgent` run through a wrapper, `scripts/probe/breakingweb/h1_wrapper.py` (written in Stage 0, hash in `design.yaml`). The clone's `_complete_bedrock` sends only `maxTokens` 4,096 and an optional temperature; it sends no reasoning or effort field, keeps only text blocks, and discards `stopReason` and usage (`agent.py:222-266`, read 2026-10-30). The history-summary call forces `temperature=0.0` and falls back silently on any exception (`agent.py:494-510`). The wrapper replaces the Bedrock call without editing the clone: it passes the reasoning setting through `additionalModelRequestFields`, sets `maxTokens` 16,384, logs stopReason, usage and the fields sent, and logs every summary-call failure. Everything else is as shipped: text only, `flatten_axtree_to_str(filter_visible_only=True, filter_with_bid_only=True)`, one action per step by bid, history trimmed at 26,000 estimated tokens with an LLM summary of dropped turns, viewport 1280x720, temperature unset.
  - Step cap: `1.5 x expected_steps` from the task YAML, the harness's own per-task budget (`agent_eval.py:417`); mean 23.4 over the sample. Wall-clock cap 1,800 s as a safety limit only. The YAML `time_limit_seconds` (60 to 90 s on 29 of the 152 pool tasks) is not used: Bedrock latency would make it a measure of throughput. Grounds: Opus-4.7 hit the 600 s wall in 199 of 516 published runs and Sonnet-4.6 in 152 of 518, so their failures partly measure the budget (on-path record §1). Step-cap hits and truncations are reported per cell and a secondary outcome excludes them (section 4.6).
  - Why primary: all six kinds reach this observation (variant gate, observation rules; [2026-10-30-variant-gate.md](../../docs/feasibility/2026-10-30-variant-gate.md)), and it is the harness of the redesign brief (D1, D2). It is also the configuration most sensitive to accessibility-tree content: no screenshot, viewport only. Heading level is never printed (0 heading lines with a level on all 7 start pages; [2026-10-29-breakingweb.md](../../docs/feasibility/2026-10-29-breakingweb.md)), so heading-level defects are out of scope.
- **Harness H2, stock browser-use 0.13.14 (secondary arm, names only).** `stock_browseruse_eval.run_episode` defaults: `use_vision=True`, up to 4 actions per step, 60-step cap, 1,200 s wall, provider `bedrock`. Its viewport code gives every Bedrock model 1024x768 (`stock_browseruse_eval.py:946-948`), so both models run at 1024x768; recorded, not changed. The footprint record captured at 1280x720 only (footprint record §2 (iv)), so the footprint is recaptured at 1024x768 on the replay states of the H2 tasks in Stage 0.
  - Why included: names is the one kind with a strong footprint in browser-use (133, 255 and 142 element lines lose their aria-label on Amazon, Gmail and the patient portal; [2026-10-30-browseruse-footprint.md](../../docs/feasibility/2026-10-30-browseruse-footprint.md) §3-4), so it is the one kind where both harnesses expose the removal and the effect can be compared across a vision-on harness. Headings and landmarks barely reach H2 (3 and 31 changed lines), and H1 predicts no effect for them either, so their harness contrast would be about 0 minus 0 and is not run.
  - Scope: Amazon, Gmail, patient portal (32 sample tasks; 31 on-path for names); cells clean, `none`, names.
- **Models.** `us.anthropic.claude-sonnet-5-5` (us-west-2; Alex's choice for the pilot, 2026-11-02) and `us.openai.gpt-5.6-sol` (us-east-2, the second model family), both reachable through `AWS_PROFILE=codex-DO-NOT-DELETE` and both answered through the wrapper on 2026-11-02 ([2026-11-02-wrapper-smoke.md](../../docs/feasibility/2026-11-02-wrapper-smoke.md) §1). MODEL RULE (Alex, 2026-10-30): only Anthropic and OpenAI GPT-5.6 models on that profile; never Gemini, Qwen or any other provider. Proposed held-out models for the main study, untouched by the pilot: `us.anthropic.claude-opus-5-5`, `us.anthropic.claude-sonnet-5`, `us.openai.gpt-5.6-terra`, `us.openai.gpt-5.6-luna` (Alex decides, section 10). Opus 5.5 ran 2 episodes on one non-sample task in the 2026-10-30 pipeline smoke; no pilot or sealed task has been run with it. Open before Stage 0: Sonnet 5.5 wrote Anthropic tool-call XML instead of the requested Python action on 86 of 170 smoke steps (smoke record W2; `READINESS.md` B-1).
  - Reasoning setting: neither allowed Claude model can disable thinking, and `budget_tokens` returns a 400 (claude-api reference, cached 2026-10-06; [2026-11-02-h1-wrapper.md](../../docs/feasibility/2026-11-02-h1-wrapper.md)). The wrapper sends adaptive thinking with `display: summarized` and effort `high` for Sonnet 5.5 (its default made explicit), and `reasoning: {effort: medium, summary: detailed}` for GPT-5.6-sol (the Bedrock default effort is [unverified]); it records the setting sent and the stop reason of every call. Grounds: the effect of an observation change moves with reasoning budget ([Enomoto2026](../../../ai-accessibility-paper/literature/papers/L_Enomoto2026.md): HTML minus a11y +17.5 at gpt-5.1 high, +8.8 at low). With `maxTokens` 16,384, Stage 0s measures the truncation rate per model; more than 2% truncated calls stops for Alex.
  - Temperature: unset (provider default). Lowering temperature only to cut variance is advised against ([Miller2024](../../../ai-accessibility-paper/literature/papers/L_Miller2024.md)), and noise persists at temperature 0 ([Bjarnason2026](../../../ai-accessibility-paper/literature/papers/L_Bjarnason2026.md), [Wei2026](../../../ai-accessibility-paper/literature/papers/L_Wei2026.md)). Stage 0s checks that the summary call's forced `temperature=0.0` is accepted by both models with their reasoning settings; if it is not, the wrapper drops the temperature for that call only (logged, applies to every cell alike).

## 4. Factors and cells

### 4.1 Kind (the treatment)

Only kinds and cells that passed all three checks: variant gate PASS and not a no-op ([2026-10-30-variant-gate.md](../../docs/feasibility/2026-10-30-variant-gate.md)), function preserved ([2026-10-30-function-equivalence.md](../../docs/feasibility/2026-10-30-function-equivalence.md)), every reference task feasible by replay ([2026-10-30-replay-feasibility.md](../../docs/feasibility/2026-10-30-replay-feasibility.md)). All are rebuilt from the frozen codemod and pass M2, M2a and M10 again before Stage 1 (section 6).

| Kind | What the source variant removes | Envs used | Status and caveat |
|---|---|---|---|
| `landmarks` | header/nav/main/footer/aside become div; landmark roles dropped | all 7 | Passed all checks. |
| `headings` | h1-h6 become div (text kept) | all 7 | Passed all checks. Function evidence weak (7 treated targets self, 65 inside). Knock-on bid losses checked by M10. |
| `names` | aria-label and aria-labelledby on every element with an interactive role | all 7 | Passed all checks on native button and link tags (1,082 treated targets). The current codemod rewrites only `button`, `a`, `Link`, `NavLink`, `Button`, `IconButton` tags; Stage 0 counts aria-labels left on any interactive role in the names build, and if any remain the codemod is widened and the build re-gated. |
| `labels` | The control's computed name from both sources: `htmlFor` (label association) and control aria-labels; visible label text kept (F68 with 4.1.2) | all 7 | Passed; clicking label text no longer focuses its control (37 labels, 6 apps). No reference path clicks a label. The label-click change is kept as part of the defect; `labels~` measures it separately. The pilot does not split association from aria-label removal (section 4.5, "Not in the pilot"). |
| `alt` | img alt | amazon only | gmail, lms, patient portal, reddit, robinhood have no `<img>` (bundle identical to clean); booking alt FAILED the gate (two seeded photos return 404). Descriptive only (10 tasks). |
| `tableheads` | th become td | gmail, lms, patient portal on-path; booking, robinhood pending | Gate saw `th` only on gmail, lms and patient portal pages; booking and robinhood cells enter only after M2. No function evidence (0 treated targets). Pilot-only kind: the sealed set has no tableheads task (section 5). |

Every kind is removed totally within its scope (DQ-dose Option A). The names half-dose (`names50`, section 4.5) is the one dose point below total.

### 4.2 Path exposure

**Question.** Does the drop come from information on the elements and pages the solution passes through?

- Exposure is a property of the task, fixed before any agent run. It is first taken from the replayed Gemini-3.1-Pro path: the primary flag of `on_path_dose.py` (an acted-on control loses a content word, becomes ambiguous or empty, for names and labels; the kind is present on a visited page, for page kinds), and the strict flag (empty or ambiguous; present in the viewport) ([2026-10-30-on-path-dose.md](../../docs/feasibility/2026-10-30-on-path-dose.md) §2.2).
  - Grounds: failure at a step usually hinges on one or two elements ([Enomoto2026a](../../../ai-accessibility-paper/literature/papers/L_Enomoto2026a.md)); DQ-dose Option D. The flag agrees across the five published models checked (names kappa 0.97, labels 0.97, headings 0.91, tableheads 0.96; same record §3.3).
  - The flags came from simulated attribute removal in the live DOM. Stage 0 re-derives them from the real frozen variants (M2b): every sample task is replayed on every frozen variant bundle, and each acted-on element's AX name is recorded in clean and variant. If simulated and real flags agree on fewer than 98% of (task, kind) pairs, the real-variant flags replace them, before Stage 1 and without agent data.
  - Study models may take other paths. Each run's realised exposure is computed from its own observations and actions (M5). Agreement between realised and assigned exposure is computed on clean and `none` runs only, where the treatment cannot shift the path. If it is below 90%, the main study re-derives exposure from the study models' screening runs (c1-c2), which are never baseline runs.
- **No off-path cells.** A kind runs only on its on-path tasks. Grounds: the on/off contrast is not estimable here. Within an env with both sides, names off-path has booking 8 (against 4 booking on-path tasks) and one task each in gmail, reddit and robinhood; labels off-path has booking 5, reddit 4, amazon 3, robinhood 2, so only booking has 5 on each side; tableheads off-path tasks (21) see no `th` on any visited page of any measured path, so their observation equals clean unless the agent deviates (cells counts from `select.json`). Requiring at least 5 tasks on each side in at least two envs, no kind qualifies. Off-path cells were also proposed as a length and format control; booking's names off-path tasks barely change (17 of 132 viewport lines on 6 of 12 pages; on-path record §3.1), so they control nothing. Length and format are handled by `fmt_wrap`, `names+` and a task-level dose covariate (section 4.5). The 276 runs saved fund `names50` and the larger `fmt_wrap` cell.

### 4.3 Model

Two models from two families, per MODEL RULE. Model is a crossed factor and every result is reported per model, because the effect of an observation change depends on the model, sometimes in sign ([Enomoto2026](../../../ai-accessibility-paper/literature/papers/L_Enomoto2026.md), [Guan2026](../../../ai-accessibility-paper/literature/papers/L_Guan2026.md); DQ-analysis finding 12). Model contrasts are computed on the tasks admitted for both models. Two models cannot show a capability trend; the pilot makes no claim about one (PREDICTIONS.md §6). The other allowed models are reserved as held-out models for the main study; a capability axis in the main study is Alex's call (section 10).

### 4.4 Repetitions

| Cell | Repeats per task and model | Why |
|---|---|---|
| clean (H1) | 6: runs c1-c2 screening, c3-c6 baseline | Screening runs set admission and are never reused as baseline, because selecting on the baseline runs biases the paired drop upward through regression to the mean (DQ-analysis "Common to every option" item 5; [Wei2026](../../../ai-accessibility-paper/literature/papers/L_Wei2026.md)). Four baseline runs give two disjoint halves for the band. |
| clean (H2) | 5: 2 screening, 3 baseline | Same rule; fewer baseline runs because H2 is a secondary arm. |
| `none`, defect kinds, `names+`, `names50`, `labels~`, `fmt_wrap` | 3 | Task count limits power more than repeats; little gain past about four units per cluster when within-cluster spread is small ([Nam2011](../../../ai-accessibility-paper/literature/papers/L_Nam2011.md); DQ-analysis finding 5). The tasks-versus-repeats split for the main study is decided from the measured variance ratio (ANALYSIS.md §8). |
| `pos_info`, `pc_break` | 2 | A large effect is expected (ours). |
| do-nothing | 1 per task and build, no LLM | The evaluator must fail an empty run in every cell (CTL-1 of [Chen2026a](../../../ai-accessibility-paper/literature/papers/L_Chen2026a.md)). Replay already found 0 of 195 on clean. |

Expected 95% half-width of a null paired drop with 4 baseline and 3 cell runs, before admission (`precision.json`, three reference settings: clean 0.7 with σ_task 1.5 and no ceiling, the old setting; clean 0.8 and 0.9 with σ_task 3.0 and 30% of tasks at ceiling, which match the 8-20% run disagreement E-R2 predicts): 64 tasks 3.8 to 7.9 points; 53 tasks 4.2 to 8.7; 46 tasks 4.5 to 9.4; 24 tasks 6.2 to 13.3; 10 tasks 9.5 to 22.8. The old setting implies 29% pairwise run disagreement, above E-R2's prediction; the pilot measures which holds. Every number is on the scale of the estimand: the mean probability-scale drop over admitted tasks.

### 4.6 Outcomes

- **Primary:** `success` from BreakingWeb's backend evaluator, per run.
- **Secondary (exploratory, registered):** success without a step-cap or truncation failure; steps to success; step-cap, truncation and wall-cap hits per cell; the first step at which a run's action differs from every clean run of the same task; on strict names tasks, wrong-target clicks among the elements that share the target's variant name (bids are stable, so this is scored mechanically); observation tokens per step and the history-trim step. Failure-class coding by BreakingWeb's belief, action and overreach classes ([Yin2026](../../../ai-accessibility-paper/literature/papers/L_Yin2026.md) §3) needs a coding protocol and is deferred to the main study.

## 5. Task selection

**Rule (written before any agent run; implemented and frozen by `pilot_plan.py select`, seed text `amt-v2-pilot-2026-10-30`).**

1. Pool: tasks in the replay reference set (input-pure Gemini-3.1-Pro solution that passes 3/3 clean replays after reset, while a do-nothing run fails; 195 tasks), not hardened after the published runs, solved by 4 to 6 of the 6 published browser-use panel models (tier A), and with no `unstable` verdict in any replay cell (drops `booking_profile_update_suite`). **152 tasks.**
2. Sample: every pool task on-path for tableheads (24; the rarest kind), then a stratified random fill by env to 64 tasks, quota proportional to each env's remaining pool with at least 3 per env. **64 tasks**: amazon 10, booking 12, gmail 9, lms 3, patient portal 13, reddit 8, robinhood 9.
3. Sealed: the other 88 pool tasks (amazon 27, booking 16, gmail 15, reddit 19, robinhood 11). No study-model run touches them until the main study.

**Grounds.** The task gate is a reference solution that the evaluator accepts 3/3 while a do-nothing run fails (brief D8; DQ-tasks Option A; CTL-1/CTL-2 of [Chen2026a](../../../ai-accessibility-paper/literature/papers/L_Chen2026a.md)). Selection never uses a study model's success under any variant, and the panel tier uses published runs of non-study models ([Gardner2020](../../../ai-accessibility-paper/literature/papers/L_Gardner2020.md), [Yao2024](../../../ai-accessibility-paper/literature/papers/L_Yao2024.md); DQ-tasks F9-F10). Tier A keeps tasks with clean headroom ([Yin2026](../../../ai-accessibility-paper/literature/papers/L_Yin2026.md); DQ-analysis finding 13). Explore on a development split and confirm on fresh data ([Gelman2013](../../../ai-accessibility-paper/literature/papers/L_Gelman2013.md), [Mintun2021](../../../ai-accessibility-paper/literature/papers/L_Mintun2021.md)).

**The sealed pool caps the main study (observed counts, simulated power).** The sealed set holds 47 strict-names, 67 primary-names, 23 strict-labels and 0 tableheads or strict-alt tasks (`select.json`). The smallest mean drop the main study detects with 80% power at one-sided alpha 0.025, median over the 96-setting grid with the range in brackets (`mde_sealed.json`):

| Sealed cell | 4 clean vs 3 cell runs | 8 vs 5 | 50 vs 50 |
|---|---|---|---|
| names strict, 47 tasks | 13.8 [10 to 17.5] | 10 [7.5 to 15] | 5 [2.5 to 10] |
| names primary, 67 tasks | 12.5 [7.5 to 15] | 10 [5 to 12.5] | 5 [2.5 to 7.5] |
| labels strict, 23 tasks | 20 [15 to 27.5] | 17.5 [12.5 to 22.5] | 7.5 [5 to 15] |
| landmarks or headings, 88 tasks | 10 [7.5 to 15] | 7.5 [5 to 10] | 5 [2.5 to 7.5] |

The task-by-cell variance does not shrink with repeats, so past about 8 vs 5 the pool, not the budget, sets the result. **Rule:** Alex sets the smallest drop the main study must detect (section 10, item 12) before Stage 0r. If it is below the 8-vs-5 median for a kind the main study will test, more reference tasks are made before Stage 1 (relaxing tier A to tiers A and B within the reference set, or new reference solutions through the same compile and 3/3 gate; replay record §2). Tasks are not moved from the sealed set into the pilot, because that lowers the main study's power further. ANALYSIS.md §8 repeats this table with the pilot's measured variance components.

**Admission (per model and harness).** A task enters a model's analysis in a harness if at least 1 of its 2 screening clean runs succeeds. Tasks that fail both stay in the run matrix and in a reported sensitivity analysis. Grounds: cells with few clean successes cannot show a drop ([Wei2026](../../../ai-accessibility-paper/literature/papers/L_Wei2026.md), Limitations). If more than a third of the sample fails admission for a model, the pilot reports that model's clean rate and Alex decides whether its reasoning setting or step cap changes. Any such change voids Stage 1: new screening runs are drawn and a new admission list is frozen (logged deviation).

**Known limits of the sample.**
- The sample is selected twice, by Gemini solving the task and by the 3/3 replay; it speaks only to such tasks.
- The development and sealed sets are not exchangeable. The sample holds every lms (3) and patient-portal (13) task; the sealed set has none. Names strict exposure is 24 of 64 in the sample and 47 of 88 sealed; amazon is 10 of 37 in the sample and 27 of 37 sealed. So every pilot estimate is also reported on the env-matched subset (amazon, booking, gmail, reddit, robinhood; 48 tasks), variance components are fitted with env as a fixed effect, and the main-study simulation reweights them to the sealed set's env composition (ANALYSIS.md §8).
- Paths come from Gemini-3.1-Pro; the study models may route differently (M2b, M5).

## 6. Manipulation checks and exclusion rules (fixed in advance)

All checks fail closed: a failed check excludes the run or cell and is logged with its reason; it is never scored as an agent failure ([Chen2026a](../../../ai-accessibility-paper/literature/papers/L_Chen2026a.md), DQ-verify B5). Every check that depends on a build runs before any agent run, so no exclusion depends on what an agent did.

| Stage | What | LLM calls | Gate to the next stage |
|---|---|---|---|
| 0 | Freeze and hash the codemod (after the names widening if needed); rebuild every bundle; M2, M2a, M2b, M3, M3a, M10; build `names_tagged` and `labels~`; implement `fmt_wrap`, `pos_info`, `names+`, `names50`, the per-step probes (M4, M5, tokens, truncation) and the run driver; write and hash `h1_wrapper.py`; recapture the browser-use footprint at 1024x768; validate the analysis code on simulated outcomes with each registered cell's exact env strata (ANALYSIS.md §7); one checkout, process and 127.0.0.1 port per (env, build), including `none`; dated literature search and close-reads of A11y-CUA and Ersoy2025; licence request to the BreakingWeb authors | none | All checks pass; simulated null rejection 2-8% at alpha 0.05; per-cell coverage 92-97% |
| 0r | Registration: `PREDICTIONS.md`, `ANALYSIS.md`, `design.yaml` frozen; their sha256 published with a trusted timestamp (Alex) | none | Hash and timestamp recorded in the run config |

| 2 | Every other run. | 3 | Analysis as registered; deviations numbered | none | |

- Day blocking puts every arm of a task in the same period, so date drift and model drift are shared within each paired comparison ([Chen2026a](../../../ai-accessibility-paper/literature/papers/L_Chen2026a.md): arms run in different periods leave drift "not excluded"; [Chezelles2024](../../../ai-accessibility-paper/literature/papers/L_Chezelles2024.md): a newer checkpoint moved GPT-4o from 23.5% to 31.4% on WebArena). Block date enters the sensitivity analysis.
- Parallelism: at most 8 concurrent episodes (16 cores, 61 GB); each episode has its own backend session and browser context. Concurrency is held constant and recorded.
- **Stopping rules** (only on infrastructure, clean data and cost; no variant result is looked at before Stage 3):
  - Rolling window: if more than 5% of the last 200 Stage-2 runs are infra-failed (M8) or call-failed (M7), stop and fix. The person fixing sees pooled counts only; any per-cell look is a numbered deviation. The fix is logged with a time stamp; runs passing M1 are kept; before/after the fix enters the sensitivity analysis as a covariate.
  - Stop for Alex if a model's screening clean success over the sample is below 30% or if the running cost exceeds 1.5x the estimate.
  - Stop a cell if any of its do-nothing runs passes (M9).
  - No early stopping for effect, futility or success.
